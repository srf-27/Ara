# M3 阶段交付（2026-11-18）

> 状态：**核心功能已落地并三方测试通过；安全层的 wss/TLS 与 GUI 的 TUN/托盘等仍缺**。本文如实区分已做/未做。

## 1. 已实现

### 1.1 房间控制面（阶段 1，`f7dabe8`）
- 房间短码（6 位）+ 创建者密码（SHA-256 salted hash，服务端存哈希、不存明文）；单房间硬上限 **8**。
- 房间列表：房间号 + 创建者昵称 + 在线人数/上限；加入必须输密码；房间之间信令与中继完全隔离。
- 验证文件：`ara-server gen-access --server host:port` 生成 `access-file.json`（服务器地址 + join token + 服务器公钥），服务端 `access.json` 保存 token，可重新生成吊销。
- 踢人/封禁：`ara-server kick --room <code>` / `--id <id>` 写 `kick.json`，服务端 5s 内执行；被踢客户端收到 `Kicked` 后拆 TUN、清 peer、删快照、停止重连。
- 本地房间快照：`%APPDATA%/ara/room.json`（Linux `~/.config/ara/room.json`），退出/断线时写，重连后以服务端为准覆写；`0600`。
- 服务端自动日志：`ara-server.log` 按天轮转（`tracing-appender`），`--log-dir` 可覆盖；客户端默认不落盘。
- 旧 M1/M2 客户端协议仍可连（`serde(default)` + legacy network/secret 分支）。

### 1.2 文件传输（阶段 2，`6cc3e5c`）
- 先请求后传输：发送方连接接收方 `VIP:43001`，发 `Request{name,size,sha256}`；接收方交互确认（`recv` 命令）或 `--auto-accept`；拒绝会带原因。
- 64 KiB 分片 + offset 校验 + 每块落盘；断点续传状态在 `transfers.json`（`0600`）；整文件 SHA-256 校验；接收端只写用户指定目录并拒绝 `../`/绝对路径。
- 结束时接收方回 `Final{ok}`，发送方据此判断真实成功/失败。

### 1.3 Windows GUI 骨架（阶段 3，`bc01011`）
- 新 crate `ara-gui`（eframe/egui），`windows_subsystem = "windows"`，运行无控制台窗口；房间表单（服务器/房间号/密码/昵称/创建）、状态栏、成员列表、日志面板。
- 通过 `UiEvent` 通道接收 Welcome/Peers/Kicked，真实连接服务器（控制面）。

### 1.4 安全（阶段 4，`866bccd`、`62d6744`）
- 接入 token 校验：有 token 配置的服务器拒绝无/错 token。
- **X25519 DH 挑战**：服务端发 nonce，客户端用与服务器公钥的共享密钥证明持有设备私钥，5s 超时；防冒用他人公钥。
- 服务器长期密钥 `server.key`（0600），公钥写入验证文件；房间密码 salted hash；本地快照/传输状态 0600。

## 2. 命令速查

```sh
# 服务端
ara-server --port 23947 --state /root/ara-state.json
ara-server gen-access --server vpn.example.com:23947
ara-server list
ara-server kick --room ABC123        # 或 --id <公钥>

# 客户端 CLI
ara up --create --password pw --nickname alice --server vpn.example.com:23947 --access access-file.json
ara up --room ABC123 --password pw --nickname bob --access access-file.json
ara rooms --access access-file.json
ara send --to 10.99.0.3 --file ./a.bin
ara recv --dir ./downloads            # 交互确认；加 --auto-accept 跳过
```

## 4. 未完成（对标 `m3-plan.md`）

1. **wss/TLS 与证书 pinning 未实现**：信令仍是明文 `ws://`，token/密码/房间列表可被同网窃听；DH 挑战只证明身份，防不了 MAC 层 MITM。这是安全层最大缺口。
2. **GUI 未接 TUN/托盘/单实例/UAC 清单**：当前 GUI 只做控制面，不建虚拟网卡；无系统托盘、无单实例、无 `requireAdministrator` 清单（运行时仍需管理员建 TUN）。
3. **GUI 未接文件传输**：进度/请求弹窗/暂停续传未做（CLI 已可用）。
4. **离线 IP 直连未实现**：`client::run` 仍强制先连服务器，`--server` 必填；「高级选项填 IP」的离线直连需改 client 入口。
5. **GUI 房间列表未接服务器**：只显示本地快照；CLI `ara rooms` 已能拉列表。
6. **日志 10MB/7 天清理未做**：只做了按天轮转；敏感字段靠"不主动记录"而非统一脱敏函数。
7. macOS 按用户要求忽略。

## 5. 风险

- 明文 ws 下，必须先在可信网络使用；不要公网长期裸跑。
- 房间/传输协议是新代码，真机多设备验收（4 人互通、切换房间、踢人、断点续传）尚未执行，只有单测与 loopback 证据。
- GUI 无 TUN，当前不能当生产客户端用。
